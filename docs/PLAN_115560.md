# CVE-2026-115560 → var_destroy → `zif_system` — scope, claim, best bets

Status: 2026-10-31. Lab-only; fixed benign command `id>/tmp/vd`. The
`var_destroy` carrier technique stays embargoed until an explicit publish
decision.

## 1. What is proven

- **End-to-end pre-auth RCE** on **patched** PHP 8.4.27 / 8.5.12 (patched for
  109618/109619, unpatched for 115560), mod_php:
  upload-progress field value → `session_start()` `php` decode → var_destroy
  UAF → forged `zend_reference`/`zend_object`/`execute_data` →
  `handlers->dtor_obj = zif_system` → `uid=33(www-data)`.
- **No application `unserialize()` sink** — the session decoder is the sink.
- **No `/proc` at fire time** on the `--brute` path: 8.5.12 full 576-slot
  `main` window found at attempt 351 (1406 s); 8.4.27 full window found at
  attempt 307 (1238.8 s). Both patched builds have full-window no-`/proc`
  results.
- Controls block: wrong `zif`, `/noswitch.php`, `upload_progress=Off`.

## 2. What is **not** proven / not claimed

- **Not default PHP.** Default `session.serialize_handler` is `php`; 115560
  needs `php_serialize`/`php_binary` configured and the app to switch to `php`
  at runtime before `session_start()`. A truly default install is not in the
  115560 threat model.
- **Not default cleanup.** The lab uses `session.upload_progress.cleanup=Off`.
  The default is `On`; the race path is public (B63) but **not verified in this
  lab**.
- **Not a default app.** Needs a loaded `__destruct` that sprays same-size
  strings and re-enters `unserialize()` (`CachePurge` is a lab model). A plain
  `shell_exec` destructor is not enough.
- **Not x86-64 general.** The no-`/proc` final is arm64 (18-bit window);
  x86-64 (~2^19) needs a leak.
- **Not multi-worker.** The lab is one prefork child for determinism; worker
  pinning/pairing at scale is not part of this proof.
- **Not arbitrary command in the harness.** The forged string carries the fixed
  benign command. The *capability* is arbitrary command execution as the web
  user; the lab intentionally does not expose it.

## 4. Best bets, ranked

### A. Port the `cleanup=On` race — **must-have for real targets**
- **Why:** default is `On`; the current direct mode is proven only with
  `cleanup=Off`.
- **How:** port the B63 streaming-upload + concurrent-consumer race; keep a
  fresh SID, a persistent first record, and the real-dtor delta; validate both
  builds.
- **Proven (2026-10-31):** streaming multipart (8×64 KiB, 0.6 s apart) to
  `/prime.php`, then a concurrent GET at `settle=0.7 s` (`?m=5`/`?m=4`) on the
  same SID. `seed.php?d=1` supplies the persistent first record (a `/prime.php`
  dummy is erased under cleanup=On). Lands on **8.4.27** (`delta=0x6d875`) and
  **8.5.12** (`delta=0x80875`), both `uid=33`. Controls: other SID (no dtor),
  `settle=6.0` (past the ~4.8 s window; only dry `inv=1`), `--bias-zif` (no
  proof), `--no-seed` (only `inv=1`). Requires 4–8 prefork children; cold-start
  delta drift (+0x1e000..0x20000) is handled by re-measure on miss. See
  `docs/RACE_WAKEUP_115560.md`.
- **Effort:** S. **Impact:** unlocks real default-cleanup targets.

### B. Find a real re-entry destructor gadget — **highest real-world impact**
- **Why:** the `spray + unserialize()` **`__destruct`** is the bottleneck.
  Public 115560 only needs a simple destructor.
- **Survey result (2026-10-31, `docs/GADGET_SURVEY_115560.md`):** **no stock
  default app combines the 115560 handler switch with a qualifying re-entry
  gadget.** The two halves live in different apps:
  - **Best real gadget:** Drupal 11 core P5
    (`YamlCacheCollectorDiscovery::__destruct` → `CacheCollector::updateCache` →
    `MemoryBackend::prepareItem` → `unserialize()`), ASAN-proven and
    self-spraying, but Drupal does **not** switch to `php` by default; it needs
    the non-default `session.storage.options.serialize_handler: php` line.
  - **Best 115560 precondition:** Roundcube's `db`/`redis`/`memcache` drivers
    run `ini_set('session.serialize_handler','php')` before `session_start()`,
    but read their own store, so the upload-progress file is not decoded; the
    native file driver does not switch. No stock re-entry gadget. CakePHP 2–5
    also switch for the `cake`/`database` session presets; no stock gadget.
  - **Correction:** `__wakeup`/`__unserialize` run under `BG(serialize_lock)`,
    so a nested `unserialize()` takes the fresh `var_hash` branch — **not** the
    UAF. Only `__destruct` runs unlocked. The earlier “wakeup variant” is
    therefore **not** a re-entry (A's wakeup test is expected negative). A class
    with both a non-throwing `__unserialize` and a `__destruct` is usable only
    via the destructor, at the overwritten (duplicate-key) placement.
  - **Version gates:** Guzzle 8 / psr7 3.x close the phpggc Drupal chain;
    `FnStream::__wakeup` (psr7 ≥ 1.9) closes FnStream compositions; Joomla's
    chain reaches the UAF but cannot emit a forged `R:`.
- **B′ result (2026-10-31):** `__wakeup`/`__unserialize` are **negative** on both
  builds (8/8 combinations, non-dup/dup); the nested `unserialize()` returns
  false because the magic call runs under `BG(serialize_lock)` (fresh branch). A
  positive `__destruct` control fires. Only `__destruct` is usable. See
  `docs/RACE_WAKEUP_115560.md`.
- **Tests:** (1) wakeup negative — done; (2) 115560 + Drupal P5 through the
  session decoder — **done, G1 PASS** on 8.4.27/8.5.12, including the
  `cleanup=On` race (`docs/DRUPAL_115560.md`); (3) phpggc `Drupal/RCE/1`
  result-use — not needed for G1. Roundcube plugin profile — **G2 PASS**
  plugin-assisted, stock db/redis blocked (`docs/ROUNDCUBE_115560.md`).
- **Effort:** M/L. **Impact:** turns the lab composition into a real,
  config-gated Drupal 11 chain or a plugin-assisted Roundcube profile. The
  underlying composition is public (`ACD421/PHP`); see
  `docs/NOVELTY_115560_2026-10-31.md`.

### C. `disable_functions`-hardened targets — **public property, our 115560 application**
- **Why:** the forged `zif_system` call reaches the real C function; the public
  simple-gadget 115560 path (`system`/`shell_exec`) is blocked by
  `disable_functions`. The property is public (TheCyberGeek, `var_dump` handler
  overwrite), but that path needs an app sink + `/proc/self/mem`; this chain
  removes the app sink. Do not claim a new bypass.
- **How:** pair A+B with a target that blocks
  `system,exec,shell_exec,passthru,popen,proc_open`; prove `id` still runs.
- **Proven (2026-10-31):** 8.4.27 at `:18203` with
  `disable_functions=system,exec,shell_exec,passthru,popen,proc_open,pcntl_exec`;
  `function_exists('system') === false` and a direct `system()` is fatal, but the
  forged `zif_system` still writes `uid=33`. Control (`--bias-zif 0x1000`)
  produces no proof. See `docs/NOFUNC_115560.md`.
- **Effort:** S once B exists. **Impact:** high (hardened apps); now demonstrated
  on the lab target.

### D. Multi-worker pinning — **deployment realism**
- **Why:** real Apache/FPM pools are multi-child; the lab is one child.
- **How:** reuse `poc/verify_worker_pinning.py`; the `main` chunk is
  fork-inherited, wrong guesses only kill children; pin and fire.
- **Proven (2026-10-31):** 8-child prefork `:18206`; the unmodified driver
  `run` works (measure pid 20 → fire pid 22), and the pinned chain with 7
  stalled holders works (measure pid 24 → fire pid 135), both `uid=33`. All
  children share the fork-inherited `main=0xffffaf000000`, `delta=0x6c019`.
  Caveat: `measure()` kills the held child, so pinning guarantees one free
  *slot* per phase, not the same PID across measure→fire; harmless because
  `main` is fork-inherited. See `docs/WORKERS_115560.md`.
- **Effort:** M. **Impact:** needed for real deployments.

### E. x86-64 seed — **broader architecture coverage**
- **Why:** the no-`/proc` final is arm64; x86-64 ~2^19 needs a leak.
- **How:** in-band leak (8.4.27 GH-22554) or `/proc/self/mem` fallback;
  8.5.12's leak is fixed, so x86-64 8.5.12 likely needs a different primitive.
- **Assessed (2026-10-31):** amd64 runs under Rosetta 2 (`:18207`). The stock
  driver's `maps.parse_maps` fails on the amd64 layout (libphp r-xp at
  `0x157000`, the `main` mapping starts one page early);
  `lab-115560/measure_amd64.py` fixes the parsing, and the unmodified `fire`
  with explicit addresses gives `uid=33`. Geometry: `main=0x7ffffc400000`,
  `lib=0x7ffffe007000`, `lib-main=0x1c07000`, `zif_off=0x46ad70`; the carrier
  delta is still `0x6c019`. This Rosetta target is deterministic (seed=1);
  native x86-64 with `mmap_rnd_bits=28` is ~2^19 and needs a leak (GH-22554 on
  8.4.27, or LFI/SSRF/XXE), not brute force. See `docs/X86_64_115560.md`.
- **Effort:** M/L. **Impact:** x86-64 targets; or accept an arm64-only claim.

### F. Publication framing — **do not overclaim**
- **Claim:** “pre-auth 115560 session decode as the var_destroy sink; no app
  `unserialize()`; forged `zif_system` dtor carrier; no `/proc` at fire on
  arm64.”
- **Do not claim:** default PHP, no gadget, first/nobody, new CVE.
- **Novelty check before publishing:** GitHub code search + Exploit-DB for the
  exact composition (“session_start var_destroy re-entry”, “115560
  var_destroy”, “session decoder var_destroy zif_system”) and for the
  forged-dtor carrier. Closest public work: `mnk-works` Chain B,
  `TheCyberGeek`/`qideng` var_destroy RCE.

| Gate | If it fails |
|---|---|
| A (`cleanup=On` race) | **passed** (both builds, multi-child + seed); the direct `cleanup=Off` path remains the simple lab profile |
| B (real re-entry gadget) | **survey:** no stock app has both halves; the stock-code path is Drupal 11 + one config line (P5), or a plugin/custom gadget. Otherwise the chain stays a lab composition. |
| C (`disable_functions` bypass) | the unique impact story weakens; fall back to the public simple-gadget path |
| D (multi-worker) | single-worker only; state the ceiling |
| E (x86-64 seed) | arm64-only claim |

As of 2026-10-31: **D is verified** (8-child + 7-holder pinning); **E works on
amd64/Rosetta** with `measure_amd64.py`, but **native x86-64 needs a leak**.

## 6. Bottom line

- **For breadth of real-world impact:** the public 115560 simple-gadget path is
  the best bet (it already gives pre-auth RCE on patched 8.4.27/8.5.12 with a
  common file-writer destructor). Our chain is not broader; it is a different
  primitive.
- **For a distinctive/hardened-target impact:** this chain is the best bet —
  no app `unserialize()` sink, forged `zif_system`, `disable_functions` bypass
  (proven on 8.4.27), no `/proc` at fire on arm64. The `cleanup=On` race has
  landed; the remaining gate is a real **`__destruct`** gadget (Drupal 11 P5 +
  one config line, or a plugin/custom gadget).
- **For publication:** frame it as a **composition/carrier** result, not a new
  vulnerability and not “default PHP.”
