# AGENTS.md — php2shell-hunt

Read this before acting. `README.md` is the product view; `docs/PIPELINE.md` is
the method.

## What this repo is

A loopback-only research program for PHP core, extension, bundled-library, and
application vulnerabilities, and the published record of what it has proven. The
primary objective is a reproducible local **RCE** on a stock-default deployment.
The scanner, manifests, and tests are support tooling, not the result.

A static candidate is not a finding. A loaded extension is not an audited
extension. A crash is not RCE until the terminal call is shown. A reproduction
of public work is not a discovery.

Every result carries a tier: `STOCK`, `CONFIG-GATED`, or `LAB-ONLY` (`GOAL.md`).
Nothing here is `STOCK`.

## Read order

1. `GOAL.md` — the RCE acceptance list, tiers, and current status.
2. `docs/RESPONSIBLE_PUBLICATION.md` — what is published, what is held, and why.
3. `docs/RCE_PATH.md` — the single active chain and missing stages.
3. `README.md` — what the repo offers.
4. `docs/PIPELINE.md` — tracks and evidence gates.
5. `docs/TARGET_SCOPE.md` — the current first-pass target.
6. `docs/BLIND_SPOTS.md` — the deferred backlog.
7. `research/*.json` — machine-readable inventories.
8. `PROGRESS.md` — append-only history.

If these disagree, the latest `PROGRESS.md` entry wins. Do not infer state from
a file name.

## Hard rules

- **Loopback only**: `localhost`, `127.*`, `::1`. No remote target, no DNS
  name, no private-network host.
- **Benign allowlist only**: `id`, `uname`, `whoami`. No reverse shells, no
  arbitrary command packaging, no mass scanning.
- **Stock defaults first**: the lab must match a default Linux/cloud install.
  No `php.ini` mount, no `-d` flags, no custom extension set, no hand-tuned
  memory/session limits. A non-default config is a labeled variant, never the
  baseline and never evidence for the holy grail.
- **RCE first**: until `GOAL.md` G2 is met, every iteration must move the
  core+app chain one rung or produce its control. Do not expand the platform,
  extension, or fuzz scope because coverage looks incomplete.
- **Evidence or it did not happen**: every claim needs a command run in this
  turn. Missing lab/image/tool is `BLOCKED`, not a zero.
- **Do not edit generated artifacts by hand**: `reports/*` is regenerated by a
  script.
- One acceptance item per iteration; append `PROGRESS.md`; run
  `scripts/check.sh` before reporting `DONE`.
- Do not weaken scope checks, tests, or manifests to make a gate pass.
- **Tier every claim.** `STOCK` / `CONFIG-GATED` / `LAB-ONLY`; a gate is named in
  one line, not implied away.
- **Credit prior art in the same paragraph as the claim.** If a delta is a port
  or a measurement, say so.
- **No held material in the tree.** The withheld `mbstring` finding and the
  disclosure drafts live only in the private working tree. Do not copy them in,
  and do not link to them; write "held pending disclosure" instead.
- Publication of a new finding is a separate decision from merging it locally.
  See `docs/RESPONSIBLE_PUBLICATION.md`.

## Tooling contract

- `scripts/scan.sh` — wrapper over `scanner/check.py`.
- `scripts/check.sh` — offline gate: compile, manifest validation, tests,
  inventory self-test.
- `scripts/inventory_extensions.py` — compare `php -m` with
  `research/extensions.json`; no audit claim.
- `scripts/lab_matrix.sh` — list/up/down/status/logs.
- Expected CLIs: `python3`, `php`, `docker`, `jq`. Missing tools are reported,
  not skipped.

## Static and fuzz standards

- Record tool, version, roots, exclusions, and time/corpus budget.
- A negative is only a negative for that tree, config, patterns, and budget.
- A result is only a result for the stated stock baseline. A custom config
  result is `CONFIG-GATED`.
- Inventory is a candidate filter. Coverage requires a function/parser map and
  a receipt.
- Coverage-guided fuzzing is required for a parser claim; blind mutation is a
  sample, not coverage.
- Every non-memory class needs an oracle (state machine, timing harness,
  invariant, browser, proxy pair) before it can produce a finding.

## Code conventions

- Python 3 standard library only; add a dependency only with explicit approval.
- Shell wrappers: `set -euo pipefail`, resolve `ROOT`, quote paths.
- Deterministic output: sorted keys, no wall-clock timestamps.
- New verifier = `poc/verify_*.py` plus an offline test.
- New reusable logic = `scanner/`, `poc/`, or `scripts/`.

## Definition of done

1. The named command ran; output is quoted or linked.
2. `scripts/check.sh` passes.
3. `PROGRESS.md` has change / verification / failure / next.
4. Any static claim names tools, coverage, and ceiling.
5. The claim names its pipeline track/stage and whether evidence is `read` or
   `executed`.
6. The iteration states which `GOAL.md` item it advances, or labels itself as
   support/control work.
